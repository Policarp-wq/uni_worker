# Контракт для вызывающего агента

## До запуска

Одна папка содержит одну работу и один канонический Markdown-источник. Разные самостоятельные работы размести в разных папках до первого запуска. При переносе сохраняй служебные файлы и историю; несовпадение сохранённых путей потребует решения человека.

Запиши рядом с работой `.critic-context.json` в UTF-8. Пути внутри JSON разрешаются относительно этого файла. Поля обязательны, кроме `assignment_files` и `decisions`:

```json
{
  "subject": "Проектирование информационных систем",
  "topic": "Практическая работа 2. Модель платёжного шлюза",
  "requirements": ["Описать события, участников и границы ответственности"],
  "previous_exists": true,
  "previous": ["../PR1/PR1.md"],
  "assignment_files": ["задание.md"],
  "decisions": ["Провайдер проводит платёж; шлюз передаёт запрос и хранит статус"]
}
```

Если предыдущих работ нет, укажи `previous_exists: false` и `previous: []`. Не приравнивай отсутствие файлов к отсутствию предыдущих работ. При `true` нужны читаемые непустые локальные MD/TXT/RST, а не PDF, DOCX, URL или имена без файлов. За полноту списка отвечает вызывающий. Требования должны происходить из задания или слов пользователя, не из предположений автора. Приложи читаемую методичку в `assignment_files`, если она доступна. Решения пользователя и допустимые отступления передавай в `decisions`.

Не расходуй попытку на незаполненный контекст: `begin` сначала проверяет входы. Отдельный агент читает локальные файлы средствами выбранного клиента; не отправляй их дополнительным сервисам без запроса пользователя.

## Команды

В примерах `SKILL_DIR` означает абсолютный путь к папке этого скилла, `REPORT` к Markdown работы. Подставляй реальные пути и заключай их в кавычки. Все команды запускаются через `python3`.

```sh
python3 "$SKILL_DIR/scripts/critic_gate.py" begin --source "$REPORT" --context /absolute/work/.critic-context.json
python3 "$SKILL_DIR/scripts/critic_gate.py" check --source "$REPORT"
```

`begin` возвращает JSON: `cycle`, `attempt`, `ticket`, `report`, `source`, `context`. Сохрани значения и передай критику. Команды `begin`, `finish`, `cancel`, `resolve` изменяют только служебные файлы этой работы; `check` только проверяет разрешение.

Пример самостоятельного задания критику:

```text
Ты отдельный критик учебного текста. Истории разговора у тебя нет.
Прочитай SKILL.md по переданному абсолютному пути и выполни ветку критика.
Предмет: …; тема: …; предыдущие работы: есть/нет, пути: …
Контекст JSON: …; текущий Markdown: …; требования: …
Цикл: …; попытка: …/3; ticket: …; твой agent ID: …
Скрипт critic_gate.py: …; рецензию запиши в …
Предыдущие рецензии и ответы автора: … / первый запуск.
Проверь стиль, сжатость, выполнение задания и преемственность.
Не меняй исходники, не генерируй DOCX. Заверши через finish.
Верни краткий вердикт и пути файлов.
```

Если клиент не предоставляет ID агента, вызывающий назначает уникальную метку отдельного запуска, например `critic-<ticket>`. Метка идентифицирует реальную независимую рецензию; она не разрешает автору проверить себя. Скрипт принимает непустую метку, но сам не подтверждает существование агента.

Если ID известен только после запуска, передай его сообщением тому же агенту до `finish`. Это часть одного запуска, не новая проверка. Не разрешай дочернему агенту повторно запускать этот скилл как вызывающий.

Критик создаёт рецензию по выданному пути, затем выполняет:

```sh
python3 "$SKILL_DIR/scripts/critic_gate.py" finish --source "$REPORT" --ticket TICKET --reviewer AGENT_ID --verdict approve
```

Другие значения `--verdict`: `revise`, `context_error`. Команда технической отмены: `cancel --source ... --ticket ... --reason 'конкретная причина'`. После `3/3` автор может разрешить конкретный спор и открыть новый цикл командой `resolve --source "$REPORT" --decision 'краткое решение автора'`. Она сохраняет старые попытки и запись решения, начинает новый цикл с `1/3`, но не выдаёт допуск. Запускай её только после явного решения автора; вручную не редактируй ledger.

Ненулевой код команды означает незавершённый переход. `check` сверяет исходник, контекст, предыдущие работы, материалы задания и последнюю попытку текущего цикла. Точные ограничения и обработка ошибок заданы в SKILL.md. Наличие решения автора не заменяет `APPROVE`: после нового цикла нужен новый допуск.

## Программный допуск к DOCX

Подключи `scripts/critic_gate.py` к каждому генератору и вызывай `require_approval(source)` до создания документа и непосредственно перед сохранением. При ошибке не создавай даже временный учебный DOCX. Для нового генератора добавь эти вызовы до первого запуска; не используй обходной экспорт через Pandoc, LibreOffice, MCP или иной скрипт.

```python
import runpy
gate = runpy.run_path(str(skill_dir / "scripts" / "critic_gate.py"))
gate["require_approval"](source)
# Создание документа из того же source.
gate["require_approval"](source)
document.save(output)
```

Генератор обязан читать именно одобренный Markdown, без собственной альтернативной версии текста. Пока идёт сборка, не меняй входы. Проверка хешей не сравнивает автоматически текст DOCX с Markdown: проверку целостности результата проводит скилл генерации.

Автоматический вызов обеспечивают правила AGENTS.md и связка со скиллами написания и генерации. Это не фоновый наблюдатель файлов: критик запускается агентом при готовности текста, а не после каждого сохранения черновика. Произвольную запись DOCX во всей ОС этот механизм не перехватывает.

## После трёх попыток

Используй эту форму передачи человеку при остановке по лимиту из SKILL.md. После явного решения автора новый цикл открывает команда `resolve`; не сбрасывай счётчик вручную:

```text
Работа: …; в текущем цикле использовано 3/3 попытки; DOCX заблокирован.
Спорный фрагмент: «…» (раздел/строки).
Критик требует: …; основание: пункт задания или критерий стиля.
Автор возражает: …; основание: требование, сохранение смысла или решение пользователя.
Что уже изменяли: …; что осталось нерешённым: …
Нужно решение человека: выбрать формулировку A/B, уточнить требование или явно
изменить правило допуска. Рекомендация автора: …, потому что …
Рецензии: ссылки на все попытки и циклы.
```

Если спора о тексте нет, назови техническую причину остановки и израсходованные попытки. Не изображай технический сбой как разногласие.

## Итоговая передача человеку

После `APPROVE`, остановки или исчерпания попыток вызывающий агент кратко сообщает человеку:

- итоговый статус работы и допуска;
- все необязательные рекомендации последней рецензии;
- другие известные ему пробелы, ограничения и риски, оставшиеся за рамками результата;
- по каждому неприменённому пункту конкретную причину отказа или переноса.

Не перекладывай эту обязанность на критика и не представляй необязательный пункт как блокирующий допуск. Если ни рекомендаций, ни известных пробелов не осталось, укажи это явно.
