# Правила выполнения практических работ Big Data

Этот файл обязателен к прочтению **до** изменения любой практической работы в `big_data`. Он дополняет общие университетские правила из родительского `AGENTS.md`; при противоречии для работ Big Data действуют правила этого файла.

## 1. Сначала определить тип работы

Перед написанием кода полностью прочитай задание и явно раздели его на блоки двух типов:

1. **Воспроизведение методички.** В задании приведён код, ожидаемый результат или готовый вывод, который требуется повторить в Notebook.
2. **Самостоятельный анализ.** Задание требует применить изученные приёмы к собственному датасету или сформулировать собственный аналитический блок.

Нельзя считать учебный блок самостоятельным только потому, что существует более удобный, красивый или современный способ его написать.

## 2. Обязательные правила для воспроизведения методички

- Переноси исполняемый код из методички в Notebook в том же порядке и без смысловых изменений.
- Сохраняй имена переменных, функции, параметры, условия фильтров, порядок операций, названия файлов, подписи графиков и формат вывода из задания.
- Не заменяй предложенный метод эквивалентом по своему усмотрению: например, не меняй фильтр, агрегаты, вычисляемые признаки, тип графика или формат экспорта.
- Не добавляй собственные признаки, пороги, фильтры, статистики, графики или «улучшения» внутрь учебного блока.
- Разрешено исправить только повреждения извлечения из PDF/Word: потерянные отступы Python, переносы строк внутри синтаксической конструкции и очевидные артефакты вёрстки. Такое исправление не должно менять логику.
- Бесполезные комментарии из источника можно не переносить, если задание прямо не требует комментариев.
- Ожидаемые результаты и готовые текстовые выводы из методички переносись в том же содержании и формате. Не пересказывай и не заменяй их своими обобщениями.
- Если фактический результат объективно зависит от окружения, фиксируй реальное значение в формате задания. Примеры: версии библиотек, время выполнения, размер Parquet после сжатия.
- Не включай в выводы артефакты PDF-вёрстки: номера страниц, колонтитулы и заголовки страниц.

## 3. Правила для самостоятельной части

- Сначала используй функции и приёмы, уже изученные в текущей или предыдущих практических работах.
- Новый для курса метод, функцию или библиотеку добавляй только если без него нельзя разумно выполнить требование или он даёт существенную пользу.
- Любой такой новый элемент явно отметь в итоговом сообщении: что это, где использован и зачем понадобился.
- Самостоятельные выводы должны опираться на полученные таблицы, расчёты и графики; не выдавай предположение за факт.
- Не выдумывай пропуски, выбросы, зависимости или ограничения, которых нет в данных и задании.

## 4. Notebook и текст

- Один логический учебный блок — отдельная последовательность Markdown-ячейки и кодовой ячейки (или нескольких непосредственно связанных кодовых ячеек).
- Перед кодом оставляй только краткое описание того, что этот конкретный блок делает. Описание обязано соответствовать коду.
- Не оставляй комментарии внутри Python-кода, если этого не требует задание.
- Не оставляй Markdown-описания, противоречащие коду, устаревшие после правок или содержащие придуманные методы.
- Если пользователь просит сначала оставить поясняющие Markdown-ячейки для проверки, сохраняй их до его явного разрешения удалить.
- Сохраняй требуемые выполненные результаты внутри финального `.ipynb`.

## 5. Проверка перед передачей результата

- Сверь каждый воспроизводимый блок с методичкой: код, параметры, ожидаемый результат и вывод.
- Проверь, что код синтаксически корректен; после существенных изменений выполни Notebook командой Run All, если среда позволяет.
- Убедись, что итоговые выводы относятся именно к данному набору, а не делают чрезмерных обобщений.
- Не изменяй пользовательские правки, которые не относятся к поставленной задаче.
- В финальном сообщении кратко укажи: какие файлы изменены, что проверено и какие новые для курса функции использованы. Если новых функций нет, прямо напиши это.
