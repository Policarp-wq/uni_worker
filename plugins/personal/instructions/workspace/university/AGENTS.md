# Общие университетские правила

Это переносимый родительский профиль. Конкретные требования задания и применимый профиль курса уточняют формат работы.

- Перед чтением PDF, DOC, DOCX, PPTX используй существующий соседний Markdown с тем же именем либо `file-to-markdown`. Не читай аудио.
- Для новой работы сначала используй `university-work-planner`, затем `university-work-executor`. Определи независимо режим общения и результат: автономно/итерационно, с отчётом/только артефакты.
- Не придумывай факты выполнения, измерения, выводы программ и личные данные. Сохраняй пользовательские решения и реальные результаты в одном плане.
- Обсуждение и драфт веди через `university-writing-style`; законченный отчёт из готовой предметной работы — через `university-report-writer` и `humanize-ru-academic`.
- Один отчёт имеет один канонический Markdown. Для готового или содержательно изменённого отчёта вызывай `university-text-critic` отдельным агентом. Автор не одобряет свой текст.
- DOCX создавай через `university-docx-report` только после действующего hash-bound допуска. Каждый генератор вызывает `require_approval` до создания документа и перед сохранением. Не обходи gate другим экспортёром или промежуточным DOCX.
- Используй только предоставленный Word-шаблон. Если обязательного ресурса или независимого агента нет, остановись с конкретной причиной.
- Личные поля запрашивай только когда формат результата их требует. Читай локальный профиль или одобренную память; недостающие обязательные значения спроси один раз. Подставляй их только в результат, не в скиллы и примеры.
- После проверки сообщи статус, оставшиеся рекомендации и причины неприменения. Не скрывай ограничения за успешным допуском.

Профили Big Data и виртуализации подключаются к выбранным папкам отдельно. Профиль виртуализации требует локальной настройки путей к генератору, требованиям и шаблону.
